# Bitácora — Agosto 2026

## 2026-08-18 — Forense LAS y estructura de adquisición

### Trabajo realizado

Se validó el primer dataset real entregado por Campo Digital y se implementaron herramientas reproducibles para:

- inspección LAS;
- cálculo de límites observados;
- análisis temporal;
- análisis de retornos;
- agrupación por GPS Time.

### Problemas encontrados

El encabezado LAS contiene límites que no coinciden con los puntos reales.

El archivo no declara CRS.

Durante el desarrollo del análisis de retornos aparecieron además problemas menores de implementación:

- parches parciales por diferencias de formato del código;
- colisión de tipos `float`/array en variables `dx`, `dy`, `dz`;
- correcciones de Ruff;
- necesidad de preservar grupos de timestamp entre límites de chunks.

Todos estos problemas quedaron resueltos y cubiertos mediante validaciones/tests.

### Hallazgos principales

El dataset contiene 9.718.909 puntos.

Se identificaron 5.609.224 grupos exactos de GPS Time:

~~~text
1 punto: 1.499.539
2 puntos: 4.109.685
~~~

Todos los grupos de dos puntos siguen:

~~~text
Return 1 -> Return 2
~~~

No existen grupos de más de dos puntos.

Los límites del header LAS son stale respecto de la geometría observada.

El CRS y las unidades siguen sin confirmarse.

### Interpretación

La nube mantiene una estructura temporal y de retornos muy ordenada, pero el archivo parece haber pasado por un proceso de conversión/exportación.

Todavía no corresponde interpretar los retornos como ecos físicos sin conocer el sensor y pipeline original.

### Decisiones

- utilizar límites observados como geometría;
- mantener límites del header para auditoría;
- no asumir CRS;
- no asumir metros;
- no llamar m³ a resultados sin confirmar unidades;
- no utilizar directamente una malla/voxel del escenario completo como cubicación comercial;
- detener la expansión del forense genérico y comenzar a trabajar sobre la ruma visible.

~~~
