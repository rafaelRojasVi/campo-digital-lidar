# Engineering journal — August 2026

## 2026-08-18 — First real LAS forensic and acquisition baseline

### Work performed

Validated the first real Campo Digital LAS and implemented reproducible streaming analysis for:

- observed LAS geometry;
- header/observed bound comparison;
- GPS-time ordering;
- return-number statistics;
- exact timestamp grouping;
- R1/R2 pair geometry.

### Problems encountered

- LAS-header bounds were stale relative to actual point coordinates.
- CRS is absent.
- The file appears to have passed through a `txt2las` export/conversion workflow.
- Incremental implementation patches initially depended too closely on formatter-specific source layout.
- A mypy issue was caused by reusing `dx`, `dy`, and `dz` as both scalar and NumPy-array variables.
- Timestamp groups needed explicit preservation across streaming chunk boundaries.

### Findings

- 9,718,909 real points are readable reproducibly.
- GPS time is non-decreasing.
- 5,609,224 exact timestamp groups exist.
- 4,109,685 groups contain exactly two points.
- Every two-point group is ordered Return 1 -> Return 2.
- No timestamp group contains more than two records.
- Some exact R1/R2 pairs have very large spatial separation.
- The visible timber wall is the next useful geometric target.

### Decisions

- geometry uses observed point bounds;
- original header bounds remain available for audit;
- CRS and linear units are not inferred;
- numeric LAS scale is not treated as physical accuracy;
- raw mesh/voxel volume is not automatically commercial cubicación;
- CloudCompare is used as a visual debugger, not as the authoritative processing workflow;
- generic acquisition forensics should no longer dominate the PoC.

## 2026-08-19 — Timber observability, front geometry, and explicit-depth volume

### Work performed

Advanced the real-data PoC from generic acquisition forensics into timber-specific geometry.

Implemented and tested:

- automatic timber-stack isolation;
- deterministic local front-view projection;
- exact 2D-to-source-LAS backprojection;
- DoG visible log-end detection;
- radial-gradient visible log-end detection;
- manual precision/recall benchmarks;
- whole-stack transverse observability tests;
- reusable front cross-section measurement;
- explicit-depth extrusion volume;
- operational `lidar volume` CLI.

### Timber-stack isolation

The automatic timber segmentation retained:

~~~text
1,342,183 points
~~~

from the deterministic candidate ROI.

Nearest-neighbour comparison against the manual CloudCompare reference showed strong geometric agreement.

### Depth observability

Multiple methods were used to search for a coherent opposite pile wall:

- transverse density profiles;
- longitudinal slicing;
- ground cleanup;
- opposite-side rendering;
- vertical-extent analysis.

No persistent coherent second vertical timber wall was found.

The apparent secondary transverse structure around approximately 5–6 source units from the visible wall was dominated by ground and other scene geometry.

### Decision

Do not infer pile depth from secondary transverse point clusters.

Do not create an artificial rear closure and report its numerical volume as measured timber volume.

Depth remains explicit until independently established.

See ADR-003.

### Visible log ends

The deterministic front projection was reproduced with:

~~~text
occupancy agreement: 100%
occupancy IoU:       100%
~~~

The radial-gradient detector became the best balanced classical baseline.

On the exhaustively labelled 70-log crop at 8 px:

~~~text
precision: 66.7%
recall:    65.7%
F1:        66.2%
~~~

Detector tuning was frozen because individual-log detection does not currently resolve hidden log length.

### Front cross-section

Baseline visible-wall measurement:

Binning sensitivity was small.

Envelope-definition sensitivity produced an approximate tested range of:

~~~text

~~~

### Reusable implementation

### CLI

`lidar volume FILE`

now reports observable cross-sectional geometry without inventing volume.

`lidar volume FILE --depth D`

calculates only:

~~~text
A_front * D
~~~

in source-units³.

For explicit depth 5:

~~~text
1085.881584 source-units³
~~~
