point-cloud dataset used locally by this PoC. The raw client data is **not**

## Coordinate reference system and units

The file contains no WKT, PROJ string, GeoTIFF keys, or other encoded spatial
reference. PDAL reports horizontal units as `unknown`.

**Consequence:** coordinate units must not be assumed to be metres, and volume
must not be labelled `m3` until the source CRS / unit convention is confirmed
from Campo Digital or another authoritative source.

The LAS scale of `0.0001` is coordinate quantization/storage resolution. It is
**not** evidence of 0.1 mm sensor accuracy, registration accuracy, or final
volume accuracy.

CloudCompare reports box dimensions of approximately `200.242 x 80.756 x

scene extents for ROI selection or volumetry. Recompute extents from the actual
points (or use a tool that does so) before downstream geometry.

## Provenance caveats

The LAS header reports:

```text
System ID: LAStools (c) by rapidlasso GmbH
Generating software: txt2las (version 181001)
```

This strongly indicates that the LAS is a processed/exported product rather
than an untouched native sensor file. The original capture sensor for this
specific dataset is not encoded in the LAS and remains unconfirmed.

The LAS header creation date (`2020`, day 111) is inconsistent with the archive
member timestamp (`2026-06-23 15:51`). Treat the header date as unreliable for
provenance until the export workflow is clarified.

Questions still requiring an authoritative answer from Campo Digital:

1. Which sensor produced this specific dataset: XGRIDS Lixel K2, GeoSun
   GS-100G, DJI Zenmuse L2, or another source?
2. What CRS and coordinate units were used at export?
3. What processing/export path produced the `txt2las` LAS?
4. What do the two-return encoding and constant point-source ID represent in
   this export?
5. Which exact physical region is the timber measurement target, and what
   reference volume exists for that same region?

## Current decision gate

No real-data volume result should be treated as meaningful until all of the
following are resolved:

1. CRS / units confirmed.
2. Source sensor / export pipeline clarified.
3. Timber ROI identified reproducibly.
4. A reference result for the same physical region is available (for example

5. Raw geometric volume is explicitly separated from any commercial cubicación

## Implementation validation: observed vs header bounds

The first real-data inspection exposed a material discrepancy between LAS header bounds and extents recomputed from the actual point records.

The inspector now treats `LasMetadata.bounds` as observed point geometry, preserves declared values separately in `LasMetadata.header_bounds`, records `header_bounds_match`, and emits a warning when the two disagree.

Validated against `v01_MG_23jun2026.las`:

- observed X: 499959.7519 -> 500159.9936; span 200.2417
- observed Y: -4166629.1194 -> -4166548.3633; span 80.7561
- observed Z: 276.2244 -> 314.6254; span 38.4010
- header X: 499928.7582 -> 500171.3969
- header Y: -4166665.9020 -> -4166516.1880
- header Z: 272.3639179 -> 317.7010396
- `header_bounds_match = false`

Downstream ROI, density, section and volume work must therefore use observed point bounds rather than trusting the LAS header extents when they disagree.

A synthetic regression test deliberately corrupts the LAS header bounds and confirms that observed geometry remains correct.

## GPS timestamp and return-group structure

Further streaming analysis tested whether the LAS return labels are
structurally associated with exact GPS timestamps.

For `v01_MG_23jun2026.las`:

- total GPS timestamp groups: 5,609,224
- one-record groups: 1,499,539
- two-record groups: 4,109,685
- maximum timestamp-group size: 2
- every two-record group is ordered Return 1 -> Return 2
- exact two-record R1/R2 groups: 4,109,685 / 4,109,685
- no two-record 2->1, 1->1, 2->2, or other patterns were observed

The exact two-record R1/R2 geometric separation is:

- minimum: 0 source units
- mean: 0.270756447 source units
- maximum: 87.9410127 source units
- mean absolute delta X: 0.174842099
- mean absolute delta Y: 0.130357711
- mean absolute delta Z: 0.094695901
- mean absolute intensity delta: 3.68782668

The exact-group result reproduces the earlier adjacent-record statistics,
showing that the large maximum separation is not caused by timestamp groups
containing more than two records.

The remaining singleton groups are also nearly balanced between return
labels: 750,146 Return-1 records and 749,393 Return-2 records.

Interpretation remains conservative. The deterministic GPS-time/return
structure is strong evidence that the export preserves a return-pair
organization, but it does not by itself prove that every exact R1/R2 pair
represents first and second physical echoes of one emitted laser pulse.
The file passed through an export/conversion workflow, and sensor/export
provenance is still required for that physical interpretation.
